# Coralline MCP

TypeScript MCP server that bridges Claude (and other MCP clients) to SuperCollider via OSC. The synthesis logic lives entirely in the SC quark (`../quark/Coralline/`); this is only the protocol translation layer.

## Architecture

```
Claude (MCP client)
    ↕ stdio
coralline-mcp (this repo)
    ↕ OSC/UDP
SuperCollider + CorallineAgent + SuperDirt
```

- **Sends to SC**: `127.0.0.1:57120`
- **Listens for pong replies**: `0.0.0.0:9501`

## Build & Run

```bash
npm install
npm run build        # → dist/index.js
npm run dev          # watch mode
node dist/index.js   # run the server
```

No tests yet — verify against a live SuperCollider instance.

## Key Data Files

Both live in `../quark/Coralline/Data/` (resolved at runtime via `paths.ts`):

- `refined_mappings.json` — 27 synths, 322 empirical timbral curves (generated by the Python probe pipeline)
- `effects.json` — categorized SuperDirt effects with ranges and descriptions

Override locations via env vars:

```bash
CORALLINE_MAPPINGS_PATH=/path/to/refined_mappings.json
CORALLINE_EFFECTS_PATH=/path/to/effects.json
```

## Critical Gotchas

### Note system
SuperDirt uses its own note numbering, **not MIDI**:
- `n=0` → C5
- `n=-12` → C4
- `n=12` → C6
- To convert from MIDI: `n = midinote - 60`

This applies to `play`, `loop_start`, and `phrase`.

### Semantic vs raw params
Semantic dimensions (`brightness`, `warmth`, `texture`, `movement`, `space`, `weight`, `attack`) are resolved by the quark into synth-specific SuperDirt params (e.g. `brightness` → `modfreq`, `velocity`, `detune` on supervibe).

**Don't send both a semantic dim and the raw params it resolves to** — raw wins and the semantic intent is silently overridden.

### loop_start hot-swap
Calling `loop_start` with an existing loop name replaces it in place via Pdef — no separate `loop_modify` tool. Playback is not interrupted.

### Pong tools are async
`get_state` and `get_audio` send an OSC ping and await a UDP reply with a 2-second timeout. If SC is not running they will time out and return an error.

### Fire-and-forget
`play`, `loop_start`, `loop_stop`, `phrase` send UDP and return immediately. There is no delivery confirmation — if SC is not running the call succeeds silently.

## Logging

All OSC traffic is logged to `logs/osc.jsonl` (JSONL format, one entry per line). Rotates to `logs/osc.old.jsonl` at 1MB. Both files are gitignored.

Log entry fields: `ts`, `dir` (in/out), `src_addr`, `src_port`, `dst_addr`, `dst_port`, `path`, `args`, `req_id` (UUID linking async ping↔pong pairs).

## MCP Tools

| Tool | What it does |
|------|-------------|
| `play` | Play a note with semantic params |
| `loop_start` | Start (or hot-swap) a named pattern loop |
| `loop_stop` | Stop a named loop |
| `phrase` | Play a one-shot phrase; supports gradient params |
| `get_state` | Query active loops (async pong) |
| `get_audio` | Query real-time audio analysis (async pong) |
| `list_synths` | List all synths and their semantic dimensions |
| `get_synth_info` | Get curve details for a specific synth |
| `get_fx` | List available effects by category |

## Source Layout

```
src/
  index.ts        server entry, tool registration, startup
  types.ts        shared TypeScript types
  osc.ts          OscClient (sender) + OscServer (FIFO pong resolver)
  logger.ts       JSONL append logger with rotation
  tools/
    play.ts       play tool
    loops.ts      loop_start, loop_stop
    phrase.ts     phrase tool
    analysis.ts   get_state, get_audio
    synths.ts     list_synths, get_synth_info
    fx.ts         get_fx
```
